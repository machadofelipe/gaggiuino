## Fixed in this branch

### R01 (high): Long-press then Cancel leaves the wrong profile highlighted (the 'no popup' bug you reported)

- **Screens:** 02 Home, 16 Profile rename keyboard; widgets `G02-10`, `C02-10`
- **Problem:** Holding a profile for 1 s sets pId to that slot before opening the rename keyboard. Cancel just returns home, which highlights pId, but trigger 07 was never sent, so the firmware keeps running the old profile with no 'Profile switched!' popup. That matches your N02-12 report: the new profile stays selected and you have to tap another one and come back.
- **Change:** program.nx: add `int pIdPrev`. home.nx tm0 long-press branch: `pIdPrev = pId` before `pId = downSlot.val`. keybdA.nx b251.up (Cancel): `if (loadpageid.val == 1) { pId = pIdPrev }`.
- **Evidence:** Simulator probe: Gemini build pId after Cancel = 2 (running slot is 1); this branch = 1.

### R02 (high): Rename + OK saves into the long-pressed slot but never loads it

- **Screens:** 16 Profile rename keyboard; widgets `G16-04`, `C16-04`
- **Problem:** Trigger 08 makes lcdFetchCurrentProfile() write to the slot shown on screen (settings.activeProfile only), while runningCfg stays on the old slot. The HMI highlights the new slot; later Saves still target the old one.
- **Change:** keybdA.nx b210.up (OK): after `printh 23 02 54 08` add `if (loadpageid.val == 1) { printh 23 02 54 07 }` so the firmware switches to the slot it just saved.
- **Evidence:** nextion.cpp:385-387 vs gaggiuino.ino:431-437 / 495-498.

### R03 (high): modeSelect stays at 'steam' (9) after the steam switch goes off on sP, bS, dS and graphPreview

- **Screens:** 13 System settings, 10 Brew options, 08 Dose & stop-on-weight, 07a Profile preview; widgets `G13-05`, `C13-05`
- **Problem:** These pages compute modeSelect once (or never). If you flip steam off while on one of them, the firmware keeps reading modeSelect=9 and starting a brew runs flushActivated() instead of the profile. pi, sk, pf and tp only recompute on load.
- **Change:** Run the same modeSelect block as sT.nx tm0 every 50 ms on pi, sk, pf, tp and dS, and add a 50 ms tm0 timer with that block to sP, bS and graphPreview.
- **Evidence:** Simulator probe (steam on, open page, steam off): Gemini = 9 on all four pages; this branch = 0.

### R04 (high): BAR/FLOW toggle desyncs the ON/OFF switch from what will be saved

- **Screens:** 03a Pre-infusion (pressure), 06 Main profile, 05a Transition (ramp); widgets `G03a-09`, `C03a-09`
- **Problem:** Trigger 06 makes the firmware call uploadPageCfg() and rewrite piState/ppState/paState and the curve from EEPROM. The page switches are only copied from those globals on load, so an unsaved 'ON' still shows ON while the global is already 0. Leaving the page saves it disabled.
- **Change:** pi/pf/tp: after `printh 23 02 54 06` set `syncTicks.val = 20`. In tm0, count down and at ticks 14 and 0 copy the globals back into the switches, then `click refUI,0`.
- **Evidence:** nextion.cpp:197-260 (uploadPageCfg) and gaggiuino.ino:470-493.

### R05 (high): Manual brew: the flow slider snaps back to 0 mid-shot after any popup

- **Screens:** 09 Manual brew; widgets `G09-26`, `C09-26`
- **Problem:** popupMSG returns by reloading bM, and bM.load does `h0.val = h0.minval`. A 'Scales tared' or 'Fill the water tank' toast mid-shot cuts the pump target to 0.
- **Change:** Add `int manFlow` to program.nx. bM.load: `h0.val = manFlow`. Update manFlow on every slider or stepper event, and reset it to 0 only on Back and on the CLEAN tab.
- **Evidence:** Simulator probe: Gemini h0 42 -> 0 after the popup; this branch 42 -> 42.

### R06 (high): Brew graph axis labels don't match the plotted values; anything above 9.7 bar is clipped

- **Screens:** 14 Live brew graph (31 s shot); widgets `G14-07`, `C14-06`
- **Problem:** s0 uses dis=140 and gdh=27. A 9 bar peak is drawn about 0.4 bar too high against the labels, and the 136 px plot tops out at 9.7 bar.
- **Change:** s0: dis=125, gdh=25, so every gridline is exactly 2 bar, 2 ml/s or 20 g, with 10.9 bar of headroom. tm0 tim=250 with gdw=40 gives exactly 10 s per vertical gridline and ~70 s on screen. Redraw the axis labels at y = 176 - 25*k in gen_assets.py.

### R07 (medium): The temperature trace is a flat line at the top, and the right axis is red (temperature) but is really weight

- **Screens:** 14 Live brew graph (31 s shot); widgets `G14-07`, `G14-11`, `C14-06`, `C14-09`
- **Problem:** At 1.4 px/°C a stable 93 °C is just a line hugging the 10 bar gridline. The right-axis numbers are red, but the only trace that uses them in practice is weight.
- **Change:** Replace channel 3 with a dim-green target-weight reference line (shotTarget/10, only when stop-on-weight is on), and colour the right axis green (grams). Temperature stays in its tile.

### R08 (medium): Shot timer shows MM:SS on the brew graph and seconds on manual brew

- **Screens:** 14 Live brew graph (31 s shot), 09 Manual brew; widgets `G14-03`, `G14-05`, `C14-03`, `C14-05`
- **Problem:** You asked for the shot timer to always be in seconds (N09-14). The brew graph still used two zero-padded numbers with a colon.
- **Change:** brewGraph: one number `n0 = activeBrewTime` (lenth=0) plus a small dim 's' suffix. Remove n1.

### R09 (medium): Flow is labelled 'g/s', but the firmware sends pump flow in ml/s

- **Screens:** 14 Live brew graph (31 s shot), 09 Manual brew; widgets `G14-09`, `G09-09`, `C14-08`, `C09-09`
- **Problem:** gaggiuino.ino:380 sends `lcdSetFlow(currentState.smoothedPumpFlow * 10)`, which is pump flow (ml/s), not weight flow. The original HMI already said g/s; the redesign copied it.
- **Change:** Label the tiles 'FLOW ml/s' on brewGraph (gen_assets.py) and bM (t0.txt).

### R10 (medium): The selected tab looks exactly like the SAVE button

- **Screens:** 12 Temperature settings, 13 System settings, 09 Manual brew, 11 Clean / flush, 03a Pre-infusion (pressure); widgets `G12-03`, `G12-05`, `C12-03`, `C12-05`
- **Problem:** Both use a solid ice-blue fill. In the sT and sP headers 'TEMP' and 'SAVE' sit side by side with the same style, so navigation and the main action can't be told apart.
- **Change:** tab*_on: raised neutral surface with a 3 px accent underline and white label (cyan underline for CLEAN). tab*_off: flat, borderless pill. Solid accent fill is now reserved for SAVE.

### R11 (medium): Transition: the curve picker is on the HOLD tab, but it shapes the RAMP

- **Screens:** 05a Transition (ramp), 05b Transition (hold); widgets `G05b-12`, `G05a-10`, `C05a-16`, `C05a-11`
- **Problem:** START/END/SLOPE are on 'RAMP', while the curve that shapes that ramp is on 'HOLD/CRV'. Rows also used a full-width layout unlike sk and pf (your N06-15 request).
- **Change:** RAMP tab = exact pf geometry (4 rows of card_204x34 plus the curve column on the right). HOLD tab = HOLD (s) and its limit as the same rows, plus an explanatory 'HOLD PHASE' diagram in the right column. Add the 'TRANS' label in front of the switch, as on sk and pf. Component order is unchanged, so the keybdB clamp ids still match.

- **Change:** Footer: PI / Soak / Trans / Main. Summary: 'MAIN 18s'.

### R13 (low): 'More' and 'SWITCH ON TRIG' are vague

- **Screens:** 03a Pre-infusion (pressure); widgets `G03a-10`, `G03a-40`, `C03a-10`, `C03a-40`

### R14 (high): The bitmap generator and test suite lived outside the repo

- **Screens:** all
- **Problem:** gen_assets.py (all 300 bitmaps), apply_redesign.py, verify_hmi.py and the overview builder were in Antigravity's private scratch folder. Nobody else can regenerate a button or re-run the checks.
- **Change:** tools/hmi/: gen_assets.py (writes build/hmi-assets, reproduces the committed pictures bit-for-bit), sync_assets.py (copies changed PNGs, appends new ones to app.toml after picture-0099), capture_screens.py, verify_hmi.py (now repo-relative, +6 assertions), check_keypad_ids.py, build_review_page.py. 9 unused bitmaps were removed.

### R15 (medium): Keypad clamps are keyed on raw component ids

- **Screens:** 15 Numeric keypad
- **Problem:** keybdB.nx clamps typed values with `loadcmpid.val == 14`. Inserting or reordering one component in a page.toml silently re-targets the clamp to another field.
- **Change:** Run tools/hmi/check_keypad_ids.py after every page.toml edit. It resolves each (page, id) to a name and fails on drift or on an editable field with no clamp. Longer term, compare against `tp.tStart.id` instead of literals.

## Next steps (explicit instructions)

### N01 (high): Firmware: the flow-mode hold limit is read from the wrong field

- **Screens:** 05b Transition (hold); widgets `C05b-20`
- **Problem:** nextion.cpp:362 reads tfProfileHoldLimit from "tp.tLim.val", but upload (line 128) writes "tp.hLim.val". The HOLD tab value is ignored in flow mode.
- **Instruction:** Change nextion.cpp:362 to myNex.readNumber("tp.hLim.val") / 10.f, then run `pio test -e test`.

### N02 (medium): Firmware: popups within 1.15 s are dropped

- **Screens:** 02 Home; widgets `C02-05`
- **Problem:** lcdShowPopup ignores any message within 1150 ms of the previous one, so 'Profile switched!' can disappear behind a tank or tare toast.
- **Instruction:** Keep the last dropped message in a static buffer and show it when the cooldown expires, instead of discarding it.

### N03 (medium): Home: the tank level (j0) has no widget

- **Screens:** 02 Home; widgets `C02-11`
- **Problem:** The firmware writes j0.val on the home page every 150 ms, but there is no j0 there, so each write fails silently.
- **Instruction:** Either add a 4x116 px vertical progress bar `j0` (bco #1F2937, pco #06B6D4) at x=162,y=80 inside the gauge card, or, if the DeLonghi has no tank sensor, guard lcdSetTankWaterLvl() in firmware.

### N04 (medium): Steppers need hold-to-repeat

- **Screens:** 12 Temperature settings, 03a Pre-infusion (pressure); widgets `C12-12`, `C12-15`
- **Problem:** Going from 93 to 145 °C steam is 52 taps, or a trip to the keypad.
- **Instruction:** Per page, add a 120 ms timer `tmRep` and a variable `repBtn`. On a stepper's .down, set repBtn and start tmRep after 400 ms; on .up, stop it. tmRep does `click <repBtn button>,1`. Clamping and RAM stay unchanged.

### N05 (low): Home: touch targets are smaller than they look

- **Screens:** 02 Home; widgets `C02-05`, `C02-10`
- **Problem:** The five profile pills are 27 px tall with 3 px gaps (~5 mm on a 2.4" panel). Fingers often land in the gap or on the neighbour.
- **Instruction:** Make each qPf hit box 30 px (y = 41 + 30*i) and bake the 3 px gap into qpf_* bitmaps (draw the pill at y=1..28 inside a 30 px image). The visual stays the same, the touch area grows by 11%.

### N06 (low): Home: the target temperature is red, like an alarm

- **Screens:** 02 Home; widgets `C02-07`
- **Problem:** The set point (n5) uses #EF4444 while the live ring is green. Red reads as 'too hot or error'.
- **Instruction:** n5 pco #F3F4F6 (neutral) and keep the crosshair icon; reserve red for the live temperature tile on brewGraph.

### N07 (low): Preview: tapping a phase band should open its editor

- **Screens:** 07a Profile preview; widgets `C07a-06`
- **Problem:** The plot already shows PI/SK/TR/MAIN bands, but only the small footer buttons navigate.
- **Instruction:** Store each band's right edge in d1..d6 while drawing. In plotBox.up, compare tch0 against the edges and `page pi|sk|tp|pf`.
